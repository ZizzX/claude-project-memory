# T-039 · Грумминг эпика board (M7) — черновик плана

Репозиторий: плагин Claude Code `project-memory` (zero-deps Node ESM, `scripts/`, тесты `node --test test/`).
Доска: `<claude-home>/projects/<repo-key>/pm/` — `tasks/T-NNN.md` (frontmatter + Goal/Understanding/Checklist/Log),
`PLAN.md`, `decisions.md`. Генерируемые виды `BOARD.md` и `board.html` пишет `scripts/lib/board.mjs` (127 строк)
после каждой команды CLI. Оба файла в `.gitignore` доски, то есть не синхронизируются между машинами.

## Как доску читают сейчас

| Вид | Кто читает | Что показывает |
|---|---|---|
| `board.html` | человек, по file:// ссылке из сводки SessionStart | 5 колонок (Todo, Ready, In progress, Waiting, Done ≤5), карточка: id, title, epic, milestone, after, @worktree, waiting, next; строка Focus; Archive-спойлер; `<meta refresh 10>`; тёмная тема через prefers-color-scheme; без JS |
| `BOARD.md` | никто в коде; человек/агент изредка | то же в markdown |
| сводка SessionStart | агент | ≤40 строк, фильтр по эпику worktree |
| `pm ready/epics/show` | агент, человек в терминале | очередь, эпики, карточка одной задачи |
| `pm status` (T-035, эпик cli, не начат) | человек в терминале | фокус, в работе, блокеры, Ready, счётчики эпиков |

Живая доска этого репо: 50 задач, 7 эпиков, board.html 13 КБ.

## Боли (наблюдения по коду и живой доске)

1. Плоские колонки при 7 эпиках: Todo смешивает все направления, нельзя увидеть «одно направление целиком».
2. Карточка — только заголовок и next. Goal, Understanding, Log, ветка, PR, решения задачи — только в md-файле или `pm show`.
3. Нет поиска и фильтров. `meta refresh` раз в 10 с сбросит любое состояние UI (ввод, раскрытые карточки, скролл).
4. Done обрезан до 5, архив эпика — одна строка со счётчиком; истории нет.
5. Решения (`decisions.md`) и план (milestones, фокус по эпикам) на доске не видны, фокус — одна склеенная строка.
6. Телефон: сетка 5×minmax(200px) → горизонтальный скролл.
7. Заголовки задач используются как описание (T-039 — 150 символов), карточки разъезжаются.
8. Зависимости `after T-039` — текст, не ссылка.

## Предлагаемый объём M7

### Шаг 1 — модель вида (новая задача, до T-040/T-041)
`boardModel(pm, tasks)` в `board.mjs`: колонки, архив, фокус по эпикам, эпики со счётчиками, решения по задачам,
детали задачи (секции md, branch, pr, последний Log). `renderBoardMd`, `renderBoardHtml` и будущий `pm status` (T-035)
рендерят из неё. Чистая функция, тестируется в node без DOM.

### Шаг 2 — T-040 (перенарезка): вёрстка и чтение
- Переключатель группировки: по статусу (как сейчас) / по эпику (дорожки: эпик → его колонки, фокус-строка эпика в заголовке дорожки).
- Карточка раскрывается (`<details>`): Goal, Understanding, Checklist, последние 3 записи Log, branch, PR-ссылка, решения задачи; `after T-NNN` — якорные ссылки.
- Вкладка/секция «Решения» (последние N из decisions.md) и «План» (milestones + фокус по эпикам).
- Адаптив: колонки складываются в одну на узком экране; заголовок карточки обрезается в 2 строки, полный — в раскрытии.
- Без JS доска остаётся читаемой (progressive enhancement).

### Шаг 3 — T-041: поиск, фильтр, сортировка на клиенте
- Данные уже в DOM (data-атрибуты карточек); встроенный `<script>` без зависимостей.
- Поиск по id/title/тексту; фильтры: эпик, статус, worktree, milestone; сортировка: order / updated.
- Состояние в `location.hash`; `meta refresh` заменить на JS-перезагрузку, которая сохраняет hash и скролл и пропускает тик, пока фокус в поле ввода.
- id непрозрачны: поиск и якоря работают и для `T-NNN`, и для будущего `PM-NNN` (T-050).

### Шаг 4 — T-042 чат агента: вынести из M7
file:// страница не может достучаться до агента/CLI без локального сервера: это новая инфраструктура
и поверхность атаки (localhost CSRF, запись доски из браузера). Замена на 80% пользы: кнопка «копировать»
на карточке (`pm claim T-NNN`, «возьми T-NNN»). T-042 → dropped или отдельное исследование позже.

## Что выкинуть
- `BOARD.md`: кодом не читается, не синхронизируется. Кандидат на удаление после появления `pm status` — вопрос вкуса.
- `meta refresh` — заменить (шаг 3).
- Жёсткий кап Done=5 — заменить фильтром/сворачиванием.

## Итог грумминга (что появится на доске)
- новая задача «модель вида board» (epic board), T-040 и T-041 перенарезаны и зависят от неё;
- T-042 → dropped (или waiting с причиной);
- решение D-0NN: объём M7, отказ от чата в M7, общая модель с `pm status`;

## Ограничения
- zero-deps; вывод генерируется при каждой команде CLI (скорость важна, 50–500 задач);
- регресс у чужих досок недопустим: доска без эпиков выглядит как раньше;
- рантайм — копия плагина в кеше, правки видны после бампа версии.

## Проверено по коду
- Ошибка в черновике: `BOARD.md` читается — `summary.mjs:59` отсылает к нему, когда сводка длиннее 40 строк. Оставляем.
- Связь решение → задача уже есть: строка `- tasks:` в `decisions.md`, `decisionsFor` (`decisions.mjs:29`). Но файл перечитывается на каждый вызов → в модели разобрать один раз и индексировать.
- `writeBoard` пишет `writeFileSync` поверх живого файла → при авто-перезагрузке можно поймать полузаписанный HTML.

## Поправки к плану (приняты автоматически)

1. **Модель:** `loadBoardSnapshot(pm)` (чтение tasks, PLAN, decisions один раз) + чистая `buildBoardModel(snapshot)` без HTML-полей; md, html и `pm status` — отдельные проекции. Контракт формы модели фиксируется в задаче до начала T-040.
2. **Безопасность:** Goal/Understanding/Checklist/Log выводятся как экранированный текст (`white-space: pre-wrap`), без рендера markdown. Ссылки — только PR-поле и только `http(s)`.
3. **Запись:** board-файлы пишутся во временный файл и `renameSync` поверх.
4. **Производительность:** бенчмарк на 50 и 500 синтетических задач до и после; бюджет записи доски на 500 задач фиксируется по замеру, не заранее.
5. **Одна карточка — один DOM-узел:** группировка по эпику делается JS-перестановкой узлов; без JS — группировка по статусу, как сейчас. Никаких дублей id.
6. **Иерархия по умолчанию:** шапка (проект, время генерации, фокус списком по эпикам) → доска → Archive → Решения (последние 10, свёрнуто). Вкладки «План» нет: milestones остаются в PLAN.md.
7. **Пустые состояния:** нет задач, нет эпиков, нет фокуса, нет решений, фильтр ничего не нашёл, все задачи dropped — у каждого своя строка текста.
8. **Зависимости:** `after T-NNN` — якорь, если карточка на доске; если задача в архиве или dropped — текст с её статусом.
9. **Телефон:** секции статусов (или дорожки эпиков) друг под другом, сворачиваемые, липкие заголовки, счётчик в заголовке.
10. **Доступность:** нативные `<details>`/`<select>`/`<input>` с `<label>`, видимый фокус, `aria-live` для числа найденных.
11. **Обновление (T-041):** состояние целиком в `location.hash` (q, epic, status, worktree, group, sort, открытые карточки); JS-перезагрузка раз в 10 с, пропуск пока фокус в поле, но не дольше 60 с; `<noscript><meta refresh></noscript>` для режима без JS; время генерации видно в шапке.
12. **Тесты клиента:** фильтр, сортировка и разбор hash — чистые функции в отдельном модуле, который встраивается в `<script>` текстом и тестируется в node; один ручной смоук в Chrome по чек-листу.
13. **Чат агента:** закрыт (T-042 dropped). На карточке — выделяемая строка команды `pm claim T-NNN`, кнопка «копировать» — необязательное улучшение.
14. **Префикс T-050:** M7 не обещает поддержку `PM-NNN`; id в коде доски считаются непрозрачными строками, этого достаточно.
