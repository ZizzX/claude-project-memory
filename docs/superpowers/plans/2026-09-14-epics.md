# Epics: several directions on one board

Date: 2026-09-14. Status: accepted, in progress (board: `pm epics` / BOARD.md of this repo).

## Problem

One board per git repository is right, but different directions (epics) run in different worktrees of
the same repo. Today `currentFocus()` returns one line per repository, the Ready line is one global queue,
done tasks stay on the board forever, and a "direction" exists only as prose in PLAN.md.

Measured on a live board of a large frontend repository (15 tasks, one epic, 5 worktrees): every worktree's summary starts with
the stop-list focus; 4 of the 5 worktrees have no task on the board at all.

## Decision

**An epic is a task field and an output-layer filter, not a directory.** Backward compatibility is free:
no `epic` → `''` → no filter, no archive, today's behaviour. No migration command.

- `tasks.mjs`: scalar `epic` (trimmed on read, last in the frontmatter literal); `isOpen`, `byEpic`,
  `activeEpic`. An empty task epic is a **wildcard** — a repo-wide task is visible in every epic view.
  `activeEpic(tasks, worktree)` = the unique non-empty epic of the open tasks claimed by this worktree
  (`worktrees` written by `claim`), falling back to all claimed tasks including done; 0 or ≥2 → `''`.
  Never derived from the branch or directory name (real case: branch `feat/APP-3032`, epic `APP-1224`;
  worktree tools often name directories with free-form slugs). The filter is applied **after** `readyQueue(all)`: the
  status map must see the whole board or a cross-epic `depends_on` makes a task never ready.
- `plan.mjs`: `currentFocus(pm, epic, keys)` reads every `## Current focus` section (split on
  `^#{1,2} `), strips HTML comments, recognises lines `- KEY: text` whose ASCII key is an epic some task
  carries (`keys`) — so `- M1: core` on a board without epics stays the plain focus, verbatim. With an
  epic → its line; with `''` and keyed lines present → `''` (no foreign focus leaks into a worktree that
  has no epic yet); the old single-line format is unchanged. `focusList(pm, keys)` for the shared board.
  `planTemplate` carries the convention in comments.
- `summary.mjs`: `· epic KEY` in the header only when resolved; Ready/Waiting through `byEpic`; Waiting
  also keeps tasks my epic's tasks depend on directly; `+N in other epics (pm ready --all)` tail;
  `Epics: KEY open/total` (open epics only); with no epic on a multi-epic board Ready shows one top task
  per epic with `(KEY)` tags. Elsewhere and Decisions are not filtered.
- `board.mjs`/`store.mjs`/`hooks.mjs`: `tasks` is read once per hook and threaded through
  `writeBoard/persist/buildSummary/lastBoardUpdate` (SessionStart 4→1 directory scans, Stop 3→1).
  Epic tag on cards; `Focus:` on the board is the list.
- `pm.mjs`: `task new --epic` (inherits the worktree's epic, prints `(epic X)` / `(epic X, new epic)`),
  `ready [--epic X | --all]` with a header line when filtered, `pm epics`. Any epic decoration appears
  only when an epic is non-empty, so boards without epics print byte-for-byte what they print today.
- Archive (M2): `archived(tasks)` = epics with no open task; hidden inside `columns(tasks, arch)`
  while `ready` is computed on the full list; on boards that have epics the Done column is capped in
  the render (full count in the heading); one `## Archive` line per epic in BOARD.md, `<details>` after
  `</main>` in board.html. An epic whose tasks are all dropped is not archived; `epic: ''` behaves as
  today, and a board without epics renders byte-for-byte as before.

## Rejected (with the reason)

- Moving `if (input.stop_hook_active) return ''` above `persist()` in `onStop`: verified by experiment
  that the re-entrant Stop is the only commit path for a manual PLAN.md edit made in reply to a block.
  A regression test pins this instead.
- `pm/epics/<KEY>/` directories, epic from branch/dir name, `pm epic archive` or an epic status,
  `[KEY]` title prefixes, banning cross-epic `depends_on`, `epic` in decisions.md, generated blocks in
  PLAN.md, `PLAN.md merge=union`, `mine.slice(0, 12)` (the MAX_LINES cut already exists and is tested).
- Clearing `worktrees` on done (loses "where the code lives before the merge"), dropping PLAN.md and
  decisions.md from `lastBoardUpdate` (would nag every session without tasks even with no code change),
  drag-and-drop on board.html (a status moved by mouse carries no did/next and no commit).

## Metrics

1. `pm summary` in each worktree of that repository starts with its own focus or a neutral one: 5/5 (was 1/5 own, 4/5 foreign).
2. Ready/Waiting lines of a worktree with an epic show only that epic's (or repo-wide) tasks: 3/3.
3. `wc -l BOARD.md` drops after an epic closes, with no manual step.
